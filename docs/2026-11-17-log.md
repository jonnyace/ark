# Session log 2026-11-16/17 — ark-library release candidate

Autonomous session building ark-library from an empty repository to release candidate 0.9.0-rc.1, on branch
`work/rc1` (local; nothing pushed). Records for resuming: PLAN.md (acceptance matrix), STATUS.md, DECISIONS.md
(D-001…D-019), TESTING.md, HANDOFF.md.

## What was built, in order
1. Inventory: upstream Lastbook (MIT, Python, pipe-only llama.cpp runner, custom map renderer), lastbook-omarchy
   (Arch packaging, PR #60), a real 7.2 GB old library on this machine. Host is headless, no WebKitGTK dev packages,
   no passwordless sudo → desktop built and tested in a pinned Docker image.
2. Early experiments: upstream runner rebuilt (llama.cpp b12032), Qwen2.5 1.5B/0.5B (Apache-2.0) measured; 1.5B
   chosen. Protomaps extract of Ithaca (1.8 MB, ODbL) + local glyphs/sprites for the sample map.
3. `lbn-core` (pure Rust, wasm-compatible): pack manifest, path safety, BM25 index shipped inside packs, citations,
   retrieval/prompt/answer checks, personal schema + migrations, catalogs, the engine API (TS generated with ts-rs).
4. `lbn-native` (store with atomic activation, resumable downloads, strict zip import, SQLite personal data with
   backups, runner control, engine dispatcher, pack builder, legacy importer) and the `ark-pack` CLI.
5. Sample library (CC0 docs/PDF/video/encyclopedia, ODbL map, two model packs), signed with a development key whose
   secret was kept outside git; it was later replaced by the publisher key (D-021).
6. Shared Svelte UI + browser engine (Web Worker + lbn-wasm + OPFS/IndexedDB + wllama) + service worker; Tauri
   desktop with `lbn://` scheme; video via a token-protected loopback responder after measuring that WebKitGTK cannot
   play media from custom schemes.
7. Tests: native install-safety suite against a real HTTP server; desktop WebDriver journey (online + `--network none`);
   Playwright suite on Chromium/Firefox/WebKit incl. offline cold start, resume, tamper, rollback, eviction, personal
   data, real browser AI, axe accessibility; clean-machine .deb install test.
8. Hardening found by tests: error-code mismatch, repair of identical damaged build, short-body download code, ask
   event race, WebKit track loading, AI loops and misread numbers (repetition penalty, loop stop, number verification).
9. Release: build/ci.sh, build/release.sh (signed SHA256SUMS), licence inventory, reproducibility check (web, packs,
   CLI, wasm, desktop binary and .deb identical across builds), docs.
